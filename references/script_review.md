# 剧本分镜审核与原格式修订规范

> 整理自 `work提示词/指令/剧本分镜审核与与原格式修订指令.txt`（原文另存于 `assets/剧本分镜审核指令_原文.txt`，可直接复制使用）。
> 定位：**中游**规范 —— 分镜稿写完后、投喂前的最后一道质检。

---

## 【任务】

对提供的原剧本分镜做**完整审核并修订**，重点检查上下镜接续、剧情表达完整度、人物站位、场景空间关系、视频生成内容适配。

**不是重新创作另一部剧本，也不是只给审核建议**；在原文基础上修正有依据的问题，最终交付保持原格式的完整修订稿。

---

## 【输入】

| 项 | 规则 |
|---|---|
| 原剧本文件 | 由用户提供 |
| 目标平台/模型/官方要求/拦截提示 | 有则提供；**未指定时只做通用风险筛查，不擅自认定某平台的具体禁限规则** |
| 人物卡/场景多视角图/道具图 | 有则共同核对；**未提供时以原剧本已明确的信息为依据，不声称已核图** |
| 单镜时长/镜数/总时长 | **以原剧本明确设定为准，不自动套用 130 镜或 15 秒** |

---

## 【不可改变的范围】

1. 保持原剧本的**剧情走向、核心事件及因果顺序、主线目标、重要伏笔与回收、核心真相、主要人物关系和结局**。不得把审核变成扩写、改编或重新设计故事。
2. 保留原有**角色姓名、身份、动机和已建立的知情范围**；保留原有场景、名称及剧情用途。**不新增、合并、替换或删除角色与场景**来解决问题，不把两个不同场景直接当成同一空间。
3. 保留**原镜数、分镜编号、镜头顺序和单镜时长要求**，不擅自增删分镜、改号、跳号或合并编号。可以在既有镜头内精简重复、补明必要过程；相邻镜之间仅在不改变事件顺序、悬念揭示位置和各镜主要用途的情况下调整细小节拍，并同步修正相关描述。
4. 优先用**最小文字修改**解决问题。允许补明不改变剧情事实的必要朝向、局部移动、取放过程、说话者和合理转场；**不得新增决定真相、人物关系或结局的证据、秘密、经历、能力与事件**。原文没有依据的关键内容不自行补成事实。
5. 保留**人物说话特点、时代背景与原作情绪**。修正生硬、重复或不清楚的表达时，不把对白统一改成另一种文风，不改变承诺、拒绝、隐瞒、指认等台词的实际含义。

---

## 【原格式必须保留】

这一节是"原格式修订"最容易违反的地方，逐条照做：

- 以输入原剧本文件为**唯一格式依据**，不套用其他示例或统一模板
- 保留：文件类型、标题层级、段落顺序、分镜标题写法、编号样式、栏目名称与顺序、时间标记方式，以及原有**字体、字号、颜色、粗体、缩进、行距、段间距、项目符号、表格与单元格结构、页面尺寸、页边距、分节符、显式分页符、页眉页脚、页码字段和已有图片**
- **在原段落或原单元格对应位置修改必要文字**，不把全文转成纯文本后按新样式重建，不自动替换字体或应用新主题
- **没有的栏目不得擅自添加**；审核所需但原文没有的状态表和检查记录只在内部维护
- 不得把审核意见、批注、修订说明、检查表或"已通过"等字样插进剧本正文，也不得把干净成稿改成带修订标记的审阅稿
- 文字修订可能引起自然分页变化 → **先精简新增说明并保留原版式设置**；不得通过缩小字号、挤压行距或删除必要内容强行恢复页数，**也不能把自然分页完全相同作为未经经验证的承诺**
- 原有显式分页与分节位置应保留
- 若当前工具无法保留原格式或某类文档元素 → **先保留原文件，明确说明具体限制，不交付重排稿冒充原格式修订稿**

---

## 【先通读全稿，再逐镜修改】

- 完整读取原文件，包括**表格中的分镜、必要的图片说明和相关附注**，不只看前几镜。先明确全剧主线、时间线、人物关系、原有场景及结局，再开始局部修改
- 内部建立简要记录（**只用于校对，不粘进每镜正文**）：
  - 各镜已发生的事件与作用
  - 人物实际位置、朝向和出入场
  - 关键道具位置、持有人及持有手
  - 伤势、服装、光线与时间状态
  - 人物知道什么、何时知道
  - 伏笔及对应回收
- **区分原文已确认事实、人物说法、推测和暂未揭晓的悬念** —— 不把角色撒谎当成作者设定矛盾，也不把合理留悬念改成提前揭晓

---

## 【一】上下镜接续审核

逐对核对**全部**相邻镜，**不抽样代替全稿检查**：

1. 本镜结束状态能否自然成为下镜起始状态？位置、朝向、姿态、手部占用、道具、时间与环境是否一致？
2. 移动、起坐、转身、开关门、出入场、取物、放物、换手、交接及物品损坏，是否有**可见过程**或有依据的时间转场？**不能只在状态说明中宣布发生**
3. 下一镜是否从上一镜的**结果**继续，而非重演已完成的动作、重新问答或再次发现同一线索？必要状态复写 ≠ 剧情重播
4. 换场、换日、回忆、插叙与返回现实是否清楚？允许省略普通路程，但必须让观众理解时间、目的与空间变化；**不强加字幕、旁白或新场景作解释**
5. 正文、状态栏、机位描述和衔接栏如原稿已有，是否互相一致？**修改一处后同步检查相关镜头**，不能只改一个字段留下旧说法

---

## 【二】人物站位与场景关系审核

1. 以原文已建立的**门、窗、桌、墙、楼梯等固定参照物**核对真实位置；不只靠"画面左、右"判断，**不凭空指定资产中不存在的参照物或方位**
2. 分清**人物自身左右、场景实际方位与摄影机画面左右**。换机位后重新判断构图；**摄影机移动 ≠ 人物换位**，不要求人物在不同拍摄方向下永远保持同一银幕左右
3. 同场对话的**视线与轴线**是否明确？如已有跨轴或大幅换向，能否用原镜内的中性机位、全景或可见移动重新建立空间？**不无故新增炫技运镜**
4. 动作在空间上能否完成？隔桌的人能否碰到对方或道具？长凳两端的人能否直接牵手？通道是否可走？移动是否穿过桌墙、其他人物或危险区？**先核起点、路线、终点，再核时间**
5. **朝向与身体动作是否相容**？两人并肩看同一方向时左右手相牵是否自然；正面对坐时伸哪只手、向哪边转头是否对应当前构图
6. 区分**场景在场人数与本画面可见人数**。切单人近景不代表其他人离场，重新入画不等于重新进门；画外说话者应有原文支持的实际位置，不强迫所有人同框
7. 道具只存在于明确位置，**不重复复制、不凭空消失、不无交接换主人或换手**。核对书本叠放顺序、屏幕朝向、物品直立或平躺等影响动作的实际状态；注意**双手是否已占用**
8. 同场**服装、伤势、光源、天气与环境损坏**等必要状态是否延续？只补当前画面确实需要的细节，不把所有细小姿势锁死，也不凭空安排状态恢复

### 分歧裁决规则

> 有多个空间解释都说得通时，以**原文明确依据最多、对后文改动最少**的解释统一；无法确定且涉及关键剧情时，**保留原意并在交付说明指出**，不能编造资产几何关系或自称全部解决。

---

## 【三】剧情表达与完整度审核

1. 检查原有事件是否缺少观众理解所必需的**触发、回应、选择、行动结果或后果**。补清原本已有的因果，**不新增另一条故事线**
2. 核对人物行为是否符合其目标、身份、能力及当前掌握的信息。**不得让角色提前知道尚未获得的事实**，也不为修顺情节擅自改变其立场或动机
3. 关键道具、证据、承诺、线索与能力是否已建立来源，后续用途是否符合前文？重大反转是否有原有铺垫，重要悬念与伏笔是否在原结局中得到回应？原稿确实缺关键依据时**如实标出，不另编真相补洞**
4. 识别**语义上的剧情重复**：换词再问、换人解释同一事实、重复威胁与保证、重复震惊、同一矛盾没有新后果地循环。**必要回指、角色各自获得信息或有新作用的呼应不应机械删除**
5. 检查是否把"他答应""她想到""众人明白"等**摘要当成已经拍出的剧情**。必要时用符合原意的简短对白、可见动作或反应落实，不新增解说旁白
6. 核对原有阶段结果与结局是否交代到位，主线目标、关系变化和重要人物去向是否可理解；不要把尚未完成的事件仅靠一句"最终解决"带过，也**不改变原作开放结局的性质**

---

## 【四】节奏与时长审核

- 对白紧凑、自然接话，剧情表达不故意拖时长。简单动作优先与对白并行，**不把看人、转头、放物逐项各留数秒**；不靠慢说、重复反应、镜尾凝视、无目的走动或长时间静物填满时长
- 按自然朗读和实际动作排演核对原有时间段。**时间标签正确不代表内容能在该时长内完成**；也不能因为原文标了较长时间，就让一句短话被故意拉长
- 必要的情绪落地和证据辨认可以保留，但应有具体作用。超时先精简重复和装饰，保留关键动作与原意；内容过少时，在不改变镜数、事件顺序和悬念位置的前提下**重分配相邻有效节拍**。前移后同步修改原位置，**不留两份，不新增同义剧情补空**
- **未进行实际配音或视频测试时，只能说明做过文字层面的节拍核对**，不能声称视频已实测达到精确时长

### 与量化核验的衔接

文字核对之外，用 `scripts/check_handoff.py` 补上可计算的量：

| 指标 | 阈值 |
|---|---|
| 单镜可承载台词 | `(时长 − 1.5秒留白) × 4.5 字/秒`（15 秒镜 ≈ 61 字） |
| 单句台词长度 | **> 40 字 = 一个人说不完**（正常语速约 9 秒） |
| 台词密度 | 超过基准 2.0 倍 = 撑不住 |
| 空镜占比 | > 15% = 在凑时长 |

---

## 【五】视频生成内容适配审核

1. 有明确目标平台时，依据该平台**当前官方规则**及可获得的模型要求核对，**不凭传闻或自造"违禁词表"下结论**。无法查证规则时说明依据与不确定性；"输入可能违规"等通用提示**不能单独证明具体触发原因**
2. 检查实际画面、动作、对白、人物年龄与关系、道具内容，以及附带的参考图、视频和音频。关注：可能受限的性化或裸露、涉及未成年人的不当内容、强烈血腥与伤害细节、自伤鼓励、仇恨或骚扰、违法行为的操作性指导，以及真实人物身份与肖像授权、素材权利问题。**不把正常家庭关系、普通医疗情节或单个词语自动判为违规**
3. 必须保持原剧情方向、人物和场景，但**这不意味着原有呈现方式一定适合生成**。对允许讲述、只是视觉细节过强或表述含混的情节 → 优先在原镜头内删去不必要的刺激性细节，改为**非露骨、非图解化**叙述、适当景别或必要反应；保留原有因果、事实与人物动机，并同步检查状态和接续。**不得为避开审核而假造年龄、身份或事实**
4. 对内容本身不被允许的情节，**不用谐音、拆字、编码、隐晦替换、画外音或"只是虚构"等说法掩盖后继续生成**。不能在不改核心剧情的前提下合规处理时 → 指出对应镜号、具体问题和需要用户决定的剧情调整，**不擅自重写核心事件，不把未解决的分镜标为可生成或已通过**
5. 核对参考素材与文字是否共同造成问题。**未查看参考图或没有授权资料时，不声称已核图、已获授权或已确认安全**；参考素材需要更换时单独说明，**不私自替换原角色、场景或文档图片**
6. **视频输入只保留修订后当前分镜及必要参考**，不把整份编剧规范、其他镜头、违规诊断、禁限示例或被替换的旧描述一起塞进输入。审核依据与问题清单放在正文外；**不要向视频模型罗列一长串无关敏感情节作为"不要生成"的说明**
7. 有平台和测试工具且用户授权测试时，可先验证代表性单镜，再依据真实反馈修正；**未实际测试时只能说明已做内容风险与表达适配审核，不能承诺"绝对合规""必过审核"或"保证跑出视频"**

> 第 6 条与 `SKILL.md` 的「每镜自足」是同一条原则的两种说法：
> **投喂给模型的内容必须只有当前镜 + 必要参考，审核过程信息一律不进正文。**

---

## 【修订与复核】

- **先定位最早出错的镜头，修正源头，再向后检查受影响的镜头**；不只在最后一镜强行改状态
- 允许分批处理，但每批携带**完整的关键状态记录**，最终合并时**不重复镜头、不拼入新旧两个版本**
- 修订完成后**重新通读全稿**，再次逐对检查相邻镜，核验：
  - 剧情方向未变、人物场景未变
  - 编号镜数与时长要求未变
  - 动作与状态一致
  - 重要伏笔与结局完整
  - 对白没有故意拖时长
  - 原有格式与文档元素保留
  - 视频内容风险已按实际依据处理，未解决项单独列明
- 格式复核同时检查**实际页面和文档结构**，不只统计字符或确认文件存在
- **凡未实际完成的检查，不得写为已通过**
- 严格保留条件使某问题无法修复时 → 不擅自越界修改；在交付说明中列明**镜号、原文冲突和需要确认的最少信息**，不把该处算作已解决。**可修复的部分继续完成，不反复要求用户逐批批准**

---

## 【交付】

- 在指定目录**另存**完整修订稿，文件名 `原文件名_接续与剧情审核修订版`，保留原扩展名；同名加编号
- **原文件不覆盖**，除非用户明确要求覆盖
- 正文只保留修订后的完整剧本，原格式不变，**不附加审核章节**
- 聊天中简短说明：主要修正了哪些问题、还有哪些未解决问题、报告真实完整路径
- 需要详细问题清单时**另存文件，不混入剧本**
- 无法保留原格式或写入指定位置时，明确说明实际限制及完成范围，**不伪称已保存、已修复全部问题或保持了未经核对的格式**

## 配套工具

| 阶段 | 工具 | 做什么 |
|---|---|---|
| 体检 | `scripts/audit_storyboard.py` | 空段、粘连、时间码、重复、跨镜引用、缺位移 |
| 核验 | `scripts/check_handoff.py` | 时长可支撑性、人物锁定、道具链、伏笔标记 |
| 语义重复 | `scripts/audit_repetition.py` | 换词再问、换人解释同一事实、重复震惊 |
| 修复 | `scripts/fix_storyboard.py` | 机械问题自动修（先备份、原子写回） |
| 导出 | `scripts/export_for_api.py` | 各平台调用包 |

机器能查的是**形式缺陷**（空段、粘连、字数、跨镜指代）；**语义重复与剧情完整性必须靠通读** —— 脚本只能给出可疑点清单，供人工确认。

## 输出格式（若用 JSON 交付修订清单）

```json
{
  "edits": [
    {"shot": 12, "field": "衔接", "new": "<整段修订后的文字>", "reason": "<一句话依据>"},
    {"shot": 7, "field": "运镜3", "new": "运镜3[00:22-00:26|...]:<整行>", "reason": "..."}
  ],
  "unresolved": [
    {"range": "分镜023-025", "issue": "<问题描述>", "reason": "<为何不能最小修改>"}
  ]
}
```

`field` 取值：风格 / 人物与声音 / 场景 / 机位 / 起始状态 / 结束状态 / 剧情作用 / 衔接 / 卡点，或 `"运镜K"`（K 为运镜序号，new 必须是完整一行）。

`new` 写**该字段修订后的完整文字**（能不改就不改）。
