# 各家 AI 视频 API 能力矩阵与通用基线

> 数据采集时间：2026-10-31。厂商参数迭代极快，使用前请以各家官方文档为准。

## 一、能力矩阵

### 时长（最关键）

| 平台 | 模型 | 单次生成时长 | 备注 |
|---|---|---|---|
| 可灵 | kling-v2-6 / o1 | **5 / 10 秒** | 文生视频、首帧图生视频只支持这两个值；用扩展功能每次 +4~5 秒，总长上限 3 分钟 |
| Seedance | dreamina-seedance-2.5 | **4–30 秒** | 任意整数秒；计费按 token（宽×高×帧/1024） |
| Seedance | dreamina-seedance-2.0 | **4–15 秒** | mini 版最低 4 秒；`duration=-1` 由模型自选 |
| Veo | veo-3 | **4 / 8 秒** | Vertex AI；每段 8 秒要拼 2 段成 15 秒 |
| Runway | gen-4 | **5–10 秒**（上限 16） | 运镜控制最强；Extend 是 Gen-3 功能，Seedance 不支持 |
| Sora | sora-2 | **12–20 秒**（API 上限更长） | 角色记忆、镜头运动 token 最好 |
| Wan | wan2.6-t2v / r2v | **2–10 秒** | 任意整数；r2v 额外支持 `shot_type: single/multi` |
| 海螺 | Hailuo | 10 秒 | 跨镜角色一致性较好 |
| Luma | ray-2 | 10 秒 | |
| Vidu | vidu | 5–10 秒 | 多主体一致性（Multi-Entity Consistency） |

### 画幅

| 平台 | 支持的 aspect_ratio |
|---|---|
| 可灵 | 16:9 / 9:16 / 1:1（另有 1:2.5~2.5:1 范围） |
| Seedance 2.5 | 16:9 / 1:1 / 9:16 / 4:3 / 3:4 / 9:16 / 自适应 |
| Veo 3 | 16:9 / 9:16 / 1:1 |
| Runway | 16:9 / 9:16 / 1:1 / 4:5 |
| Sora 2 | 16:9 / 9:16 / 1:1 |
| Wan 2.6 | 16:9 / 9:16 / 1:1 / 4:3 / 3:4 |
| 抖音 / 快手 / 微信视频 / 小红书 | **9:16** 为主 |

**全平台交集：16:9、9:16、1:1。竖屏短剧用 9:16，无争议。**

### 分辨率

| 平台 | 竖屏 9:16 常用值 |
|---|---|
| Wan 2.6 | 480×832 / 720×1280 / 1080×1920 |
| Seedance 2.0 | 480p(854×480 级别) / 720p / 1080p / 4K |
| 可灵 | 720p / 1080p |
| Runway | 最高 4K |
| 平台建议（抖音/快手/微信/小红书） | 1080×1920 |

**通用选择：1080×1920（9:16, 1080p）。** 若要覆盖全部平台，720×1280 是更安全的下限。

### 参考图

| 平台 | 上限 | 引用方式 |
|---|---|---|
| 可灵 | 参考图 + 主体数之和 ≤ 7（有参考视频时 ≤ 4） | 图片作为主体参考 |
| Seedance 2.0 | 9 张 | 描述里称 "Image 1 / Image 2" |
| Seedance 2.5 | 30 张（总素材 ≤ 50） | `metadata.image_role` 显式声明用途 |
| Wan 2.6 r2v | 图 0–5 + 视频 0–3，合计 ≤ 5 | `character1` / `character2` / `character3` |
| Runway / Veo / Sora | 支持 | 视具体端点 |

**通用安全值：≤ 5 张参考图**（Wan 的合计上限是最大的约束）。

### 负向提示词

| 平台 | 独立字段 | 长度上限 |
|---|---|---|
| Wan 2.6 | ✅ `negative_prompt` | 500 字符 |
| Runway Gen-4 | ✅ | — |
| Seedance | ✅ | — |
| Veo 3 | ✅ | — |
| 可灵 | ⚠️ 写在 prompt 里（"避免出现…"） | — |

**通用写法：负向约束写两遍** —— 一份独立的 negative_prompt 字段（给支持的家），一份用自然语言嵌在 prompt 末尾（给不支持的家）。

### 音频

| 平台 | 原生音频 | 对白口型 |
|---|---|---|
| 可灵 2.6 | ✅ 可开关（pro 档支持 voice 定制） | ✅ prompt 里用引号包住台词即触发口型同步 |
| Veo 3 | ✅ 同步生成 | ✅ |
| Seedance 2.0/2.5 | ✅ 可开关 | ✅ |
| Sora 2 | ✅ 原生多声道 | ✅ |
| Runway Gen-4 | ❌ | ❌ |
| Wan 2.6 | ⚠️ 需外挂 `audio_url`（wav/mp3，3–30 秒） | ❌ |
| 海螺 / Luma | ❌ | ❌ |

**通用策略**：台词用引号包住（触发口型），同时准备外挂音轨给不支持音频的平台。

### 连续性机制

| 平台 | 首帧续写 | 末帧回传 | 首尾帧（两张图） |
|---|---|---|---|
| Seedance 2.0 | ✅ | ✅ `return_last_frame` | ✅ `last_frame_image` |
| Wan 2.6 | ✅ | ✅ | — |
| 可灵 | ✅ 首帧图 `image` | ✅ 扩展功能 | — |
| Runway | ✅ | ✅ | — |
| Veo 3 | ✅ | ✅ 扩展功能 | — |

**几乎所有平台都支持首帧续写** —— 这是无状态流水线里唯一可靠的"记忆"。

`export_for_api.py` 提供三种模式（`--continuity`）：

- `first`（默认）：同场戏内每段用上一段末帧作首帧，跨场断开。零额外出图，最快。
- `keyframes`：先批量出每镜关键帧静帧（数量 = 该平台切分后的段数 + 1），每段用相邻两张作首/末帧，中间运动交给模型。静帧便宜、可先审，适合锁起止构图。末帧仅 Seedance 2.0 两张图模式支持；其他平台退化为只用首帧。
- `off`：不做帧控制，纯文生视频测试。

> 首尾帧慢的不是出图，是反复抽视频。把关键帧当静帧批量出、先审后生成，比逐段抽视频快；但日常批量仍建议 `first`。

## 二、通用基线（写稿时的硬约束）

### 段长：5–10 秒

**这是最重要的一条。**

- 下限 4 秒：Seedance 2.0 / Veo 3 / Wan 2.6 都以此为下限，低于会直接报错
- 上限 10 秒：可灵、Runway、Wan、海螺、Luma 都是 10 秒封顶
- **5 秒和 10 秒是所有厂商都支持的档位** —— 首选
- 段长 < 4 秒的段，必须与相邻段合并后再投喂

对照本技能服务的剧本形态：

| 原稿形态 | 现段长 | 是否通用 | 改法 |
|---|---|---|---|
| 15 秒/镜，4 段 | 3–5 秒 | ⚠️ 偏短 | 合并为 **2 段（7–8 秒 + 7–8 秒）** |
| 30 秒/镜，8 段 | 3–4 秒 | ❌ 太短 | 合并为 **3–4 段（8+8+8+6 秒）** |
| 15 秒/镜，3 段 | 4–6 秒 | ✅ 基本可用 | 不用改 |

### 单镜多次生成 vs 一次生成

- **一次生成一整镜（15/30 秒）**：只有 Seedance 2.5（≤30s）和 Sora 2 支持。其余全部不支持。
- **通用做法**：每镜拆成 2–4 段，各段独立生成，靠**首帧续写**串起来。

### 参考图 ≤ 5 张

一镜只用：
- 出场角色的三视图（通常 1–2 人）
- 关键道具图（1–2 张，纯白背景单件图）
- 场景参考图（1 张）
- 必要时上一镜末帧（首帧续写）

超过 5 张会超出 Wan 的上限；`export_for_api.py` 按 **角色 > 关键道具 > 场景** 截断。

### 参数模板（通用字段名）

大多数平台用 OpenAI 兼容或近似 schema，字段名基本一致：

```json
{
  "model": "<平台模型名>",
  "prompt": "<该段完整提示词>",
  "negative_prompt": "<负向约束>",
  "duration": 5,
  "aspect_ratio": "9:16",
  "resolution": "1080p",
  "seed": 12345,
  "reference_images": ["<角色三视图>", "<场景图>"],
  "first_frame_image": "<上一段末帧>",
  "audio": true,
  "watermark": false
}
```

差异点：

| 字段 | 差异 |
|---|---|
| 时长字段名 | `duration`（可灵/Seedance/Runway）/ `duration_seconds`（Wan 2.6）/ `seconds`（Seedance 火山方舟） |
| 分辨率字段名 | `resolution`（可灵）/ `metadata.resolution`（Seedance）/ `size`（Wan，写 `1080*1920` 具体像素） |
| 参考图字段名 | `reference_images` / `images`（Seedance）/ `reference_urls`（Wan r2v）/ `refer_image`（可灵） |
| 首帧图 | `image`（可灵）/ `metadata.image`（Seedance）/ `first_frame_image`（通用习惯） |
| 末帧图 | `last_frame_image`（Seedance 2.0 两张图模式） |

**适配脚本应当把这些差异抹平**，见 `scripts/export_for_api.py`。

## 三、分层投喂：核心层 + 详情层

### 为什么要分层

**行业铁律**：单条 prompt 别超过 80–100 词，超过会让模型困惑、输出变糊。

但逐镜流水线要保连续性，光靠核心层不够（空间锚定、道具状态、负面约束都是长文本）。所以**把连续性信息从画面描述里拆出来**：

```
prompt_core    画面本体：风格 + 人物 + 动作 + 镜头 + 光线 + 台词
               → 直接喂模型。控制在 ~120 中文字以内（≈80 英文词的语义量）

prompt_detail  连续性与约束：空间锚定 / 道具状态 / 画风细则 / 负面 / 防重复
               → 预算紧或模型对长提示词敏感时可省略

prompt_minimal = 只用 core
prompt_full    = core + detail（默认）
```

### 产出格式

`export_for_api.py` 的每个平台目录下：

```
kling/
├── manifest.json      每段含 prompt_core / prompt_detail / prompt
│                      params（=core+detail）与 params_minimal（=core）
│                      以及 prompt_chars 词数统计
├── prompts.txt        人读的逐段提示词（默认用 core）
└── segments/*.txt     每段一个文件，按 core / detail 分节
```

### 怎么选

| 情况 | 用哪版 |
|---|---|
| 默认（想保连续性） | `params`（core + detail） |
| 预算紧 / 模型对长提示词敏感 | `params_minimal`（只用 core） |
| 参考图很强（角色一致性已锁死） | `params_minimal` 通常够用 |

### 核心层的三条压缩原则

1. **删元标注** —— "可见人物1人（…）"对画面无意义，抽出为每镜一行
2. **镜头术语单独归位** —— 含"镜头/推近/特写"的句子归入镜头层，不与画面描述混排
3. **风格取短版** —— 完整风格放详情层，核心层只留一句"真人写实电影质感，4K，浅景深，竖屏9:16"

### 实测

《等雨停》12 镜 → 可灵 24 段：核心层平均 ~100 字（限 120），详情层 ~250 字，全量 ~350 字。
改造前是单层 651 字。

## 四、平台适配检查清单

投喂前逐条确认：

- [ ] 段长在 4–10 秒之间，且不超过目标平台的单次上限
- [ ] 段数 × 段长 = 目标镜时长（拼接后总长正确）
- [ ] aspect_ratio = 9:16
- [ ] 分辨率用具体像素或该平台接受的档位名
- [ ] 参考图数量 ≤ 5（且不超过该平台上限）
- [ ] 台词用引号包住（给支持原生音频的平台触发口型）
- [ ] 负向约束既写在 negative_prompt 也嵌在 prompt 末尾
- [ ] 每一段有可见的人物位移 + 镜头跟随
- [ ] 同段内的构图/景别不重复
- [ ] 段间衔接靠首帧续写或关键帧（不是靠文字描述）；用 `keyframes` 模式时已备好关键帧静帧
- [ ] 每段单独可读：无"上一镜/第NNN镜/承接"
- [ ] 固定 seed 便于复现（重跑同一段时）
